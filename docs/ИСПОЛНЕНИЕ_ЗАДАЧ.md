# Доски и экономное исполнение

Перед работой: `pm.py context`, затем `pm.py work queue` для явных запусков с
доски или `pm.py work next` для выбора следующих задач. В MCP — `tt_work` с
соответствующим `op`. Новый запрос сначала записывается `tt_remember` как запрос,
затем декомпозируется `tt_work op=plan`. Не начинать реализацию до записи плана.

План содержит project и массив tasks: id, title, why, root, size (S/M/L), priority
(🔴/🟡/🟢), risk (low/medium/high), work_type
(docs/test/implementation/architecture/research), acceptance (список проверяемых
критериев), depends_on (id задач того же проекта). XL разбивается. Весь план
проверяется до записи; дубли, циклы и чужие корни отклоняются. Приём заметок и
сбор фактов по-прежнему не меняют ручной бэклог автоматически.

## Доски

`py tools/pm.py serve` → вкладка «Доски задач». Каждому проекту соответствует
отдельная доска. Фильтры: проект, поиск, статус, приоритет, только фокус.
Фокус сохраняется в данных и доступен всем исполнителям. Рекомендации сортируются
по фокусу, приоритету, затем размеру. Это объяснимая начальная эвристика;
заблокированные, закрытые, уже принятые и непроработанные задачи исключаются.
Кнопка «Приоритет» циклически переключает три уровня. «Паспорт» показывает
критерии, модель и бюджет; «Проработать задачу» позволяет уточнить критерии,
тип работы, риск и явный выбор модели с model_reason.

«Новая задача» и «Проработать задачу» открывают обычные формы: название, цель,
исходный запрос, критерии, срок, размер, приоритет, риск и модель. Для пакетной
декомпозиции ассистент использует plan через CLI/MCP. Исходный запрос выбирается
из памяти проекта; новый запрос создаётся через remember. В автономном HTML изменения недоступны:
запустите локальный сервер. Природное дерево остаётся отдельной вкладкой.

Режимы «Доска» и «Список» используют одинаковые фильтры; выбор режима и фильтры
сохраняются в браузере. Счётчики показывают выбранную выборку: открыто, срок в
ближайшие семь дней, просрочено, завершено. Пустой срок не считается просроченным.
В паспорте отмечаются проверенные критерии; изменение текста критериев сбрасывает
отметки. Ручное завершение (complete) требует всех отметок и доказательства,
запрещено при активном запуске. Старые done-задачи не получают выдуманных отметок.

Фокус-сессия: 25 минут, пауза/продолжение, +5 минут, завершение. Состояние и
время окончания сохраняются в браузере и синхронизируются между его вкладками.
Это личный таймер, не измеритель времени работы модели и не управление системными
уведомлениями. Кнопка «Оформление» переключает светлую и тёмную тему.

## Запуск и результат

«Запустить» создаёт запись RUN-n в очереди. **Это очередь для подключённого
исполнителя, не фоновый процесс модели.** Приложение Codex не предоставляет этому
Python-серверу интерфейс создания чатов. Доска не переключает модель текущего чата.
Исполнитель читает очередь, выбирает нужную модель в своей среде и принимает
запуск. Если требуются полностью автономные запуски без открытого ассистента,
нужен отдельный адаптер исполнения; текущая очередь сама их не выполняет.

MCP-пример (ref имеет вид project/task-id):

```json
{"op":"enqueue","ref":"project/TASK-1"}
{"op":"claim","ref":"project/TASK-1","run":"RUN-1","worker":"идентификатор чата","model":"gpt-6-luna"}
{"op":"finish","ref":"project/TASK-1","run":"RUN-1","evidence":"Результат и конкретные проверки","tokens":4500}
```

Ошибку записывают через fail, остановку — cancel, с evidence. История сохраняется,
повторное принятие запрещено. Перед claim снова проверяются зависимости и паспорт.
Работающий паспорт менять нельзя. Завершение требует непустого доказательства,
но истинность проверки оценивает исполнитель: строка evidence сама не запускает тесты.
Расход tokens включает вход, выход, reasoning и повторы; если неизвестен, поле
пропускается. Неизвестное не выдаётся за ноль. Статусы и приоритеты меняют канонический
бэклог явной командой, поэтому видны дереву и расчётам после пересборки.

CLI: `pm.py work request путь.json` выполняет такую же операцию из файла;
`pm.py work packet project/TASK-1` выдаёт пакет; `pm.py work models` — каталог
и накопленные измерения. API: GET/POST `/api/work`, запись только с X-TaskTreker: 1
на локальном сервере. Записи workflow сериализуются файловой блокировкой, отдельные
файлы заменяются атомарно. Не редактируйте projects.json параллельно с операциями
доски; общей транзакции с внешними редакторами и Obsidian нет.

## Выбор модели и экономия

Каталог — снимок моделей, доступных в этом хосте Codex на 19.10.2026, а не обещание
доступа через API. Перед исполнением проверять реальную доступность. Каталог и
начальные правила лежат в `tools/workflow.py`; источник —
[официальная документация выбора моделей](https://developers.openai.com/api/docs/guides/model-selection).

Для небольшой определённой задачи с низким риском используется Luna, для обычной
разработки и интеграций — Sol, для высокого риска или исследовательских задач —
Astra. Это стартовые эвристики, а не доказанное превосходство на задачах портфеля.
Старые модели доступны для явного выбора. Без типа и риска рекомендация помечена
предварительной. Обоснованный ручной выбор хранится в задаче. Мощнейшая модель
не назначается всем задачам по умолчанию.

Пакет ограничен 6000 символами, ориентир начального контекста — 2000 токенов.
Сначала паспорт, затем контекст одного проекта и адресные recall/поиск файлов.
Общий ориентир расхода: 6000/12000/24000 токенов для классов задач, максимум две
неудачные попытки на одной модели. Эти числа — начальные настройки, не измеренные
нормативы. После двух ошибок или исчерпания записанного бюджета повторный запуск
на той же модели блокируется: нужно декомпозировать либо обосновать другую модель.
Активную сессию сервер не может остановить по токенам: лимит в ней соблюдает агент.

Не использовать дополнительные модели для форматирования, сортировки и вычислений,
которые делает код. Не перечитывать неизменные файлы и полный портфель; хранить
решения и указатели в памяти. Не пересылать всю историю следующему исполнителю.
Кеширование и сокращение входа/выхода согласуются с
[рекомендациями по стоимости](https://developers.openai.com/api/docs/guides/cost-optimization).

После исполнения сохранять проверенный результат и полный известный расход.
Сравнивать долю успешных задач, токены с повторами и одинаковые критерии приёмки;
измерения по моделям доступны через models. Пока выборка мала, не объявлять модель
«идеальной» и не обещать процент экономии. Тариф API и цена подписки различаются.

## Проверка

`py -m unittest discover -s tests -q`, `node tests/boards_smoke.cjs` (Playwright,
локальный сервер; TT_URL задаёт адрес), `py tools/pm.py check` перед слиянием.
Видео-референс просмотрен 19.10.2026: доска/список, компактные карточки, фильтры,
метрики, чек-листы и фокус-сессия. Это адаптация выбранных сценариев к TaskTreker,
а не полное воспроизведение показанного приложения: календарь встреч, командные
аватары, каталог обоев и управление уведомлениями ОС не реализованы.
