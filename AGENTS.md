# Работа с TaskTreker

Перед изменением данных прочитай `CLAUDE.md`: он остаётся общим регламентом проекта
для Claude, Codex и ChatGPT. Начинай с `py tools/pm.py context`; подробности читай
точечно через `status`, `recall` или MCP `tt_*`.

Не переписывай ручные данные автоматическим сбором, не редактируй генерируемые JSON
и `dashboard.html` вручную. Изменяй исходники в `tools/`. Сохраняй природную
визуализацию дерева. После изменений запускай тесты; перед слиянием — `pm.py check`.
Работа ведётся в ветке `разработка`, без прямых коммитов в `тестирование` и `main`.

Перед реализацией нового запроса записывай декомпозицию в TaskTreker: корень запроса,
задачи, зависимости, критерии приёмки, размер, риск и вид работы. Затем
`py tools/pm.py work queue` / `next` / `packet <проект/id>` (или `tt_work`).
Используй модель и бюджет из паспорта; не выбирай самую мощную автоматически.
Результат фиксируй с проверками. Контракт: `docs/ИСПОЛНЕНИЕ_ЗАДАЧ.md`.

Интеграции и команды: `docs/ИНТЕГРАЦИИ.md`. Сводка проверенного состояния:
`docs/СОСТОЯНИЕ_ПРОЕКТА.md`. Не сохраняй копии личных данных портфеля в этот файл.
