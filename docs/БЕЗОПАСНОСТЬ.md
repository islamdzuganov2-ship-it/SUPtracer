# Безопасность TaskTreker — что защищено, чем доказано, чего нет

Источник требований — пакет «TaskTreker 3.0 Security Expanded» (`04_SECURITY_ARCHITECTURE_AUDIT_TZ.md`,
SEC-001…024, SEC-TC-01…30). Задачи — TT-120…TT-131 в бэклоге проекта `tasktreker`.
Тесты — `tests/test_security.py` (кейсы названы по номеру SEC-TC) плюс перечисленные ниже наборы.

Главный принцип: **разрешение на выпуск дают только машинные доказательства, полученные сервером на конкретном
коммите**. Текст агента, отметка в отчёте или запись в файле руками не превращаются в PASS.

## 1. Модель угроз в двух строках

LLM-агент пишет недоверенный код и тексты; он может ошибаться, «чинить» проверку вместо кода, получить prompt
injection из README и попытаться выйти за свою задачу. Владелец — единственный, кто меняет политику, эталон
приёмки и выпускает в main. Всё, что делает агент, проверяет сервер, а не сам агент.

## 4. Честные пределы — чего нет

- **Изоляция файлов (SEC-009 п.2, SEC-TC-16/17).** Недоверенный код (шаги CI, verify локальной модели, мутации)
  `job_runner` запускает от имени пользователя песочницы `tt-sandbox`, если владелец сохранил его учётные данные
  в диспетчере Windows (`cmdkey /generic:tasktreker-sandbox /user:tt-sandbox /pass`). Нужны ещё ACL владельца:
  запрет на `data/`, изменение — только каталоги рабочих копий. Лимиты Job Object те же. Нет учётных данных или
  рабочая копия вне этих каталогов — прежний режим `job` под владельцем. Сработавший режим пишется в
  `CompletedProcess.sandbox`. `TASKTREKER_SANDBOX_USER=require` запрещает запуск без песочницы.
  Сессии ИИ-агентов (CLI Claude/Codex) по-прежнему идут под владельцем: им нужен его профиль и учётные данные ИИ.
  Тесты — `test_sandbox_user` (SEC-TC-16/17 пропускаются без учётных данных).
- **Токен сессии дашборда** защищает от чужих сайтов в браузере, но не от процесса того же пользователя:
  такой процесс прочитает страницу. От локального вредоносного кода защищает только изоляция выше.
- **SBOM и полный аудит зависимостей (SEC-013)** — нет; pip-audit только по явному включению (сеть).
- **Метрики ИБ (SEC-021) и property/mutation-тесты (SEC-022)** — не реализованы.
- **Внешние сканеры** на этой машине не установлены: Bandit, Semgrep, Gitleaks, pip-audit — `not_run`.
  Обязательными их делает владелец: `security.required` в настройках, тогда NOT_RUN блокирует выпуск.
- **Пределы памяти рантайма модели** (SEC-TC-19) не ставятся: рантайм — отдельный процесс владельца.

## 5. Команды

```bash
py tools/pm.py security status                 # сводка по портфелю
py tools/pm.py security scan <проект>          # прогнать сканеры в рабочей копии
py tools/pm.py security findings <проект>      # находки последнего скана
py tools/pm.py security triage <key> --verdict accepted_risk --why "…"   # только терминал владельца
```

Через MCP: `tt_work op=security action=snapshot|findings|scan` (триаж — только владелец на доске).
Изменение эталона приёмки одобряет владелец в колокольчике («🧪 Изменён эталон приёмки») — `op=approve_oracle`.
