# GPT / Codex, ChatGPT Desktop и Claude

TaskTreker использует один источник истины — `data/`. Ассистенты подключаются к
существующему MCP-серверу и читают брифинги, память и задачи инструментами `tt_*`.

Для досок и исполнения добавлен `tt_work`: plan, list, queue, next, packet,
models, focus, settings, update, enqueue, take, claim, heartbeat, finish/fail/cancel,
split. Задача назначается ИИ (`executor`: claude или codex). Два ИИ могут параллельно
вести один проект: метка `claimed_by` с арендой и области `scope` не дают им взять
одну задачу или править одни файлы. После обновления
перезапустите MCP-подключение, чтобы клиент получил новый инструмент.
Контракт и ограничения запуска: [ИСПОЛНЕНИЕ_ЗАДАЧ.md](ИСПОЛНЕНИЕ_ЗАДАЧ.md).
Ключ API для этой интеграции не нужен: модели запускаются в приложении ассистента.

## Подключение

```powershell
py tools/pm.py connect --provider codex
py tools/pm.py connect --provider claude
py tools/pm.py connect --provider all --status
```

`codex` добавляет `[mcp_servers.tasktreker]` в `$CODEX_HOME/config.toml` или
`~/.codex/config.toml`. Используются абсолютные пути Python и сервера. Посторонние
настройки сохраняются, исходный конфиг копируется в `config.toml.tasktreker-backup`,
повторное подключение не меняет файл. Если имя занято другим сервером или TOML
нельзя безопасно отредактировать, команда возвращает ошибку без перезаписи.

По [официальной документации MCP](https://learn.chatgpt.com/docs/extend/mcp),
локальные ChatGPT Desktop, Codex CLI и расширение IDE используют общую MCP-конфигурацию
одного хоста. После подключения перезапустите MCP-серверы в настройках приложения
или начните новую сессию. Вызовите `tt_projects`, затем `tt_context` с проектом
`tasktreker`, чтобы проверить доступ к данным.

`claude` сохраняет прежнюю установку пользовательского MCP и хука начала сессии.
Команда без `--provider` по-прежнему означает Claude. `--provider all` подключает оба
клиента. Отключение: `py tools/pm.py disconnect --provider codex` (либо `claude`, `all`).

В веб-ChatGPT локальный `config.toml` не обеспечивает доступа к компьютеру.
Для него требуется отдельно установленный поддерживаемый удалённый MCP/plugin.
TaskTreker не публикует личные данные и не открывает сервер в интернет.
Подключение MCP также не означает автоматическое чтение всех переписок ChatGPT.
Готовый Markdown можно принять существующей командой `pm.py ingest`.

## Получение данных

```powershell
py tools/pm.py refresh --fast --source all
py tools/pm.py refresh --fast --source codex
py tools/pm.py refresh --fast --source claude
py tools/pm.py serve
```

В шапке приложения есть выпадающий список «Получение данных из»: GPT / Codex,
Claude Code или оба источника. «Источники и подключение» показывает отдельные
токены, сессии, время, свежесть и состояние MCP; оттуда можно подключить ассистента.
Выбор сохраняется в браузере. Обновление одного источника сохраняет последний сбор
второго. Общие показатели портфеля объединяют источники; это указано в интерфейсе.
При открытии HTML как файла кнопки показывают соответствующую команду.

Claude: `~/.claude/projects`, с поддержкой `CLAUDE_CONFIG_DIR`.
Codex: `$CODEX_HOME/sessions` и `archived_sessions`. Сборщик читает только метаданные
расхода, рабочий каталог и модель. Тексты сообщений не копируются в `usage.json`.
Повторы накопительных счётчиков и копии архивных сессий не увеличивают расход.
Кеш входит во входные токены, reasoning входит в выходные: второй раз не считается.
Проекты определяются по `path` и `usage_paths` с предпочтением самого длинного пути.

В `usage.json` сохранены прежние поля `projects`, `total`, `scan`; добавлены `providers`
и `by_provider` у проекта. Старый формат мигрирует как Claude. `usd` — известная часть
API-эквивалента, а `cost_complete: false` отмечает неполный тариф. Стоимость GPT / Codex
считается по [официальному прайсу OpenAI](https://developers.openai.com/api/docs/pricing),
проверенному 14.10.2026: Standard API, вход, выход, чтение и запись кеша.
Для запросов >272 тыс. входных токенов применяются опубликованные правила длинного
контекста; накопленные токены всей переписки не подменяют размер запроса. GPT-5.5
использует правило длинной сессии. Публичные модели и датированные снимки имеют
проверенные тарифы; внутренние имена вроде `codex-auto-review` остаются неизвестными.
Тариф не переносится с похожей модели и не считается счётом подписки.
Денежные диаграммы показывают известную часть. Прогноз тоже помечается, если исходный
расход оценён не полностью. Недоступные журналы не обнуляют последний успешный сбор.

Обновление останавливается при первом неуспешном шаге и возвращает ненулевой код.
Завершённые шаги могут сохранить данные; снимок при ошибке до сборки не создаётся.

## Проверки

Обновление `--source codex` или `all` также импортирует содержание локальных сессий:
проект → сессия GPT / Codex → запрос → итоговый ответ. Отдельная команда:
`py tools/pm.py codex-memory [--dry-run]`. Текст хранится в приватной `data/memory/`,
а `data/codex_sessions.json` содержит перечень сессий и обнаруженных проектов.
Инструменты, reasoning, служебные инструкции и промежуточные комментарии не импортируются.
Копии журналов и возобновлённые сессии объединяются по ID; история, унаследованная
подагентом, не становится его новыми запросами. Ручные правки и забытые записи сохраняются.
Неизвестные проекты видны отдельными ветвями дерева и карточками «вне ручного портфеля»;
`projects.json`, готовность и бэклог автоматически не переписываются.
По запросу владельца обнаруженные проекты регистрируются после сверки исходных
документов. После регистрации они используют общий путь: технический срез,
сделанное, статус, полный бэклог, оценка остатка, карточка и дерево — независимо
от ассистента. `project_activity.py` обновляет сведения о сессиях и статусах
задач из явно указанных `tracking_documents` без перезаписи ручного бэклога.
Если численная готовность не оценена, `readiness.assessed: false` показывает
«не оценено», а не выдуманный процент. Статическим проектам можно указать
`scan_include_dirs: ["dist"]` и `web_sources: true`: авторский HTML/CSS/JS в
этом каталоге войдёт в технический срез. Для новых проектов с одним источником
оценка остатка использует медиану проектов того же ассистента, если такая история есть.
Рабочие копии `.codex/worktrees` сопоставляются по точному уникальному имени
каталога из `path`/`usage_paths`. Обновление Claude сохраняет импорт Codex.

Все локальные пути и Claude-slug определяются через `project_routes.py`.
Разные продукты одного семейства не объединяются по общему префиксу или истории
клона. Если правила владения поменялись, выполните `refresh --source all`: выборочный
сбор помечает устаревшую маршрутизацию другого источника и гейт блокирует слияние.
`inspection_path` выбирает активный checkout для фактов и отслеживаемых документов;
он не добавляет его метрики к метрикам исходного клона. `history_since` задаёт
временную границу собственной истории, а `related_projects` — только навигационную
связь отдельных карточек. Ревизия и критерии разделения описаны в разделе 11
`docs/ТЗ_01_Память_Obsidian_Дерево.md`.

```powershell
py -m unittest discover -s tests -q
py tools/pm.py check
```

Дополнительно `node tests/browser_smoke.cjs` проверяет работающий локальный сервер:
выбор источника, сохранение выбора, диаграммы, заставку и поиск дерева, карточки и
узкий экран. Нужны Playwright и установленный Edge; адрес задаётся `TT_URL`, браузер —
`TT_BROWSER`. По умолчанию адрес `http://127.0.0.1:8790/`.
