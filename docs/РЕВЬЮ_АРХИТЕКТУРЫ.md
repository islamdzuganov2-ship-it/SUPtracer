Роль: архитектор решения и senior fullstack. Предмет: ветка `разработка` на коммите
`7e98df8` (доски, экономное исполнение, интеграция Codex). Проверялись архитектура,
реализация, удобство, функциональная достаточность и визуализация. Особый фокус —
исполнение задач несколькими ИИ. Природное дерево (`tree.js`, `tree.py`) в этой
работе не менялось.

Серьёзность: **высокая** — неверные данные или потеря работы; **средняя** —
заметные неудобства, хрупкость или риск в будущем; **низкая** — гигиена кода.
Статус: **исправлено** (в этой работе, задачи TT-35…TT-40) или **в бэклоге** (номер задачи).

## Итог

Основа здоровая. Один источник истины в `data/`, разделены ручные и генерируемые
слои, атомарная запись файлов, проверки на входе, гейт перед слиянием, контракт
исполнения «план → паспорт → запуск → доказательство». Слабым местом было исполнение.
Каталог моделей знал только одного поставщика ИИ, метки занятости не было, и два ИИ
не могли безопасно работать в одном проекте. Ещё нашлась ошибка в тарифах Claude,
из-за которой денежный счёт портфеля был завышен.

## Функциональная достаточность

- **Выбор ИИ.** Задаётся на задаче (`executor`), неявно через явную модель или
  настройкой по умолчанию. Для неназначенной задачи доска показывает обе альтернативы.
  Fable 5.1 и старые модели автоматически не назначаются.
- **Параллельная работа.** Каждый ИИ работает в своём клиенте (Claude Code, Codex)
  через тот же MCP: `next agent=<свой>` → `take` → `heartbeat` → `finish`. Метку видят
  оба ИИ, доска, брифинг и бэклог.
- **Распределение.** `split` делит свободные задачи проекта, балансируя по очкам размера.
  Цепочка зависимостей и задачи с общей областью уходят одному ИИ. Строгая цепочка
  не распараллеливается — предпросмотр так и говорит.
- **Не сделано сознательно.** Автономный запуск моделей сервером: у приложений Claude
  и Codex нет интерфейса создания чатов извне, и ключи API здесь не используются.
  Очередь остаётся очередью для подключённого исполнителя.
