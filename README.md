# TaskTreker — портфель проектов

Одна панель по всем вашим проектам сразу, в двух вкладках:

- **Дашборд** — диаграммы и цифры: готовность по пяти измерениям, вложено против оставшегося,
  цена пункта готовности, затраченное время, количество и качество ТЗ, качество проработки,
  расход по месяцам. Плюс десять портфельных сигналов с уровнем «норма / следить / действовать».
- **Проекты** — полная информация: что сделано, бэклог с размерами и оценкой затрат,
  безопасность, архитектура, мощности, LLM, цели, оценка и конкуренты.

Работает локально, без сервера, без сети и без зависимостей — только Python из стандартной
библиотеки. Дашборд открывается двойным кликом по `dashboard.html`.

Чем отличается от счётчиков расхода вроде `ccusage`: расход токенов здесь — одна колонка
из десяти, а не вся панель. Чем отличается от Jira: половина данных собирается сама, с диска
и из журналов, а не вбивается руками.

## Быстрый старт

```bash
git clone https://github.com/islamdzuganov2-ship-it/SUPtracer.git && cd SUPtracer
```

```bash
py tools/pm.py init
```

Разложит примеры в рабочие файлы. Впишите свои проекты в `data/projects.json` — главное поле
`path`, по нему собирается и код, и расход токенов. Затем:

```bash
py tools/pm.py refresh
```

Соберёт всё: расход токенов из журналов сессий → технический срез репозиториев → оценку
оставшихся задач → дашборд → снимок для истории. Открыть: `py tools/pm.py open`.

## Комментарии превращаются в бэклог

Мысль по проекту записывается одной командой и при следующем разборе становится задачей:

```bash
py tools/pm.py comment мой-проект "Перед релизом проверить, что дебаг-флаг выключен" --kind техдолг
```

Виды: `техдолг`, `идея`, `баг`, `вопрос`. Разбирает их ассистент по регламенту из
[CLAUDE.md](CLAUDE.md): определяет размер, переносит в бэклог нужного проекта и помечает
комментарий обработанным с указанием, куда именно он ушёл. Ничего не удаляется — разобранный
комментарий остаётся следом решения.

## Сводка в терминале

```bash
py tools/pm.py status
```

```bash
py tools/pm.py status мой-проект
```

## Что измеряется само

| Метрика | Откуда берётся |
| --- | --- |
| **Затраты** — токены и деньги | журналы сессий, дедупликация по `requestId` |
| **Время** — активная работа | отметки времени в журналах: сумма промежутков между ответами, паузы длиннее 15 минут отброшены как перерыв |
| **Количество ТЗ** | коды требований в документах, схемы нумерации, объём и структура |
| **Качество ТЗ** | трассируемость (какая доля кодов требований встречается в коде), дисциплина документирования, плотность открытых вопросов |
| **Качество проработки** | тесты, версионирование, гигиена поставки, чистота кода, подозрение на секреты |
| **Цена пункта готовности** | потраченные деньги, делённые на процент функциональной готовности |

Индексы качества — взвешенная сумма нормированных компонент. Каждая цифра раскладывается
до компоненты с её весом и сырым значением, поэтому её можно оспорить по существу.
Пороги нормировки — в [`tools/quality.py`](tools/quality.py).

## Как считаются затраты

**Факт.** Журналы сессий Claude Code (`~/.claude/projects/*/*.jsonl`) содержат `usage` каждого
ответа. Сборщик дедуплицирует по `requestId` — **каждый ответ пишется в журнал дважды, и без
дедупликации расход завышается ровно вдвое**. Проект определяется по `cwd`, рабочие деревья
(worktrees) сворачиваются в родительский проект.

Это решает известную проблему: Claude Code не размечает запросы метаданными проекта, поэтому
привязать расход к проекту напрямую нельзя.

**Деньги** — эквивалент по прайсу Anthropic API, а не счёт подписки. Считаются раздельно вход,
выход, запись кеша (1.25× от входа при TTL 5 минут, 2× при часе) и чтение кеша (0.1×). Прайс
в [`tools/pricing.py`](tools/pricing.py).

**Прогноз.** Размер задачи (S/M/L/XL) переводится в коммиты, коммит — в токены по
**фактическому расходу в этом же проекте**. Где своей истории мало, берётся медиана портфеля.
Это стоимость работы ассистента, а не трудозатраты человека.

## Ветки

Три ветки, движение строго в одну сторону:

```
разработка  →  тестирование  →  main
```

| Ветка | Что это | Что в неё попадает |
| --- | --- | --- |
| `разработка` | рабочая, здесь живёт вся текущая работа | любые правки: данные, инструменты, документация |
| `тестирование` | проверочная | только то, что прошло `py tools/pm.py check` |
| `main` | стабильное состояние | только то, что отработало в тестировании |

Прямые коммиты в `тестирование` и `main` не делаются — туда сливают из предыдущей ветки.

**Гейт между ветками:**

```bash
py tools/pm.py check
```

Четырнадцать проверок: целостность данных (обязательные поля, диапазоны готовности, обоснование каждой
цифры, уникальность задач бэклога), согласованность ручного слоя с автоматическим (весь расход
разнесён по проектам, оценка покрывает бэклог, разобранные комментарии указывают куда
перенесены), отсутствие ключей в данных и то, что дашборд собирается со всеми проектами.
Код возврата 1 — сливать нельзя.

```bash
git checkout тестирование && git merge --no-ff разработка && py tools/pm.py check
```

## Автоматизация

Два уровня: факты обновляются без участия модели, суждения — с ним.

| Что | Когда | Стоит токенов |
| --- | --- | --- |
| **Факты**: токены, репозитории, оценки, дашборд, снимок | ежедневно, планировщик ОС → [`ops/refresh.cmd`](ops/refresh.cmd) | нет |
| **Суждения**: разбор комментариев, сверка записанного с фактами, отчёт | еженедельно, запланированная задача ассистента | да |

Ежедневная задача трогает только генерируемые файлы. Готовность, бэклог, оценка и
безопасность меняются либо еженедельным разбором, либо прямой командой.

Регистрация ежедневной задачи в Windows:

```bash
schtasks /Create /TN "TaskTreker\Обновление портфеля" /TR "%CD%\ops\refresh.cmd" /SC DAILY /ST 09:00 /RL LIMITED
```

## Что где лежит

```
data/
  projects.json      ИСТОЧНИК ИСТИНЫ, ведётся вручную: цели, сделанное, готовность,
                     бэклог, безопасность, архитектура, мощности, оценка
  competitors.json   конкуренты по каждому проекту и в чём превосходство
  comments.json      комментарии → бэклог и техдолг
  usage.json         АВТО: токены и деньги из ~/.claude/projects
  repos.json         АВТО: git, объём кода, тесты, TODO, гигиена, подозрение на секреты
  estimates.json     АВТО: оценка оставшихся задач в токенах и деньгах
  quality.json       АВТО: индексы качества и портфельные сигналы
  snapshots/         история для трендов — не удалять
  *.example.json     примеры структуры (единственное, что попадает в репозиторий)
tools/
  pm.py              командная строка
  collect_usage.py   разбор журналов сессий с дедупликацией по requestId
  collect_repos.py   сканер репозиториев
  estimate.py        оценка бэклога по фактическому «токенов на коммит»
  quality.py         индексы качества ТЗ и проработки, портфельные сигналы
  build_dashboard.py сборка dashboard.html (данные вшиваются внутрь)
  charts.js          диаграммы на инлайновом SVG, без библиотек
  app.js             рендер вкладок
  shell.html         каркас страницы
  check.py           проверки перед слиянием
  pricing.py         прайс Anthropic API (сверяется раз в 60 дней)
dashboard.html       собирается, руками не править
CLAUDE.md            регламент обновления — читать перед правкой данных
```

> **Рабочие данные не публикуются.** `data/*.json` и `dashboard.html` — в `.gitignore`:
> в них пути вашей машины, внутренние оценки проектов и находки по безопасности.
> В репозитории только `*.example.json` со структурой. Прежде чем снимать это исключение,
> посмотрите, что именно окажется в открытом доступе.

## Требования

Python 3.10+ (проверено на 3.14), только стандартная библиотека. Git — для среза репозиториев.
Ничего не устанавливается и никуда не ходит по сети.
